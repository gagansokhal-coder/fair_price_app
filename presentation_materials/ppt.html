01

The Problem

  • India's PDS serves 81.35 crore beneficiaries under NFSA — the world's largest food security program
  • Annual ration diversion estimated at ₹1 lakh crore due to supply chain corruption
  • Current verification relies on paper-based dealer self-reporting — a fundamental conflict of interest
  • Citizens have no digital mechanism to report non-delivery or short-weighing of rations
  • District officers lack real-time ground-truth data — corruption stays invisible until delayed audits
  • Middlemen exploit opacity to divert subsidized grains to black markets, depriving poorest families
LOK DIKSHA · NIT Jalandhar
02

Empathize the User

👨‍🌾 Citizens (NFSA Beneficiaries)

  • Travel kilometers to FPS — told "no stock" despite dispatched supplies
  • Semi-literate — cannot navigate complaint portals or file written grievances
  • Fear retaliation from FPS dealers if they complain directly

👨‍💼 Government Officers

  • BDOs manage hundreds of FPS shops with no real-time dashboard
  • DMs need actionable intelligence for surprise inspections
  • Current system trusts the supply chain — LOK DIKSHA trusts the citizen
LOK DIKSHA · NIT Jalandhar
03

Our Solution: LOK DIKSHA

  • A mobile-first citizen verification platform that empowers NFSA beneficiaries to report ration delivery status
  • GPS geofencing (100m radius) — citizens must be physically at FPS to participate
  • One-device-one-citizen binding prevents proxy voting and identity fraud
  • Hierarchical poll targeting — District → Subdivision → Block → Village level precision
  • Zone classification: GREEN >80% YELLOW 50-80% RED <50%
  • Role-based admin dashboard for DMs, SDOs, and BDOs with real-time analytics

Anti-Fraud & Security

1
Poll Active Check
Verify poll exists, is active, and not expired
2
Option Validate
Bounds-check selected option index against poll options
3
Duplicate Detect
Block re-voting with DB unique constraint + app check
4
LGD Eligibility
Citizen must reside in poll's target LGD area
5
GPS Geofence
PostGIS 100m radius check against FPS shop location
6
Atomic Insert
Conflict-rejecting INSERT with unique constraint fallback
  • Device Binding: Hardware UUID locked to one citizen account permanently
  • Rate Limiting: 1 vote per user per 60 seconds (brute-force prevention)
  • Mock Location Detection: Android API detects GPS spoofing apps

08

Database Architecture

📊 Core Tables

  • lgd_hierarchy — 13,000+ Punjab villages with full path (State→District→Block→Village)
  • users — Citizen accounts with ration card, phone, device UUID, GPS, LGD codes
  • officers — Admin accounts with role, jurisdiction codes, designation
  • otp_sessions — OTP verification tracking with expiry

📋 Polling Tables

  • custom_polls — Dynamic polls with JSONB options (2-5 choices), LGD targeting
  • custom_poll_responses — Citizen votes with GPS coords, distance, unique constraint
  • poll_results_summary — Materialized view aggregating option-wise vote counts
  • PostGIS — ST_DistanceSphere for geospatial validation queries
LOK DIKSHA · NIT Jalandhar
